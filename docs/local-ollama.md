# 本机 Ollama 图文 embedding 验证

日期：2026-10-25。范围：下载模型并做五张真实照片 smoke test；没有启动全库索引，没有恢复暂停的产品开发。

## 已验证配置

- Ollama 服务版本：0.40.8（沿用已安装服务，没有升级）。
- 地址：`http://127.0.0.1:11434`
- 模型：`hf.co/ggml-org/embeddinggemma-2-GGUF:Q8_0`
- 接口：Ollama 原生 `POST /api/embed`。
- 图片输入：`input: {"image": "<base64>"}`；文本输入：`input: "查询文本"` 或字符串数组。
- 权重来源：https://huggingface.co/ggml-org/embeddinggemma-2-GGUF
- 本次下载清单：文本模型 309855456 字节，projector 554821024 字节；Ollama 下载后完成 SHA256 验证。
- 向量维度：768；图文使用同一模型。模型报告的 271M 是文本 GGUF 参数量，不代表额外 projector 不存在。
- 测试请求使用 `keep_alive: "10m"`；模型可在空闲后卸载，下次请求重新加载，未更改全局常驻设置。

## 测试结果

使用现有照片的已生成派生图，不修改原图：白花、生日蛋糕、鸟、狗、猫共五张。

- 中英文各五条查询，在五张候选中的 Top-1 均为 5/5。
- 首张图片请求 2.094 秒，其中模型加载约 1.304 秒。
- 后续四张单图编码约 0.354–0.693 秒。
- 五条中文文本批次约 0.049 秒；五条英文文本批次约 0.028 秒。
- 所有输出均为同维度、有限、非零向量，不同图像未产生相同向量。
- 原有 1000 张图片 SHA256 全部再次校验通过。

这是精选少量易区分样本的接入验证，不是整库准确率，不验证复杂否定/关系/主观偏好，也不能从这些计时直接推算全库吞吐。

## 复现

从仓库根目录运行：

```sh
.venv/bin/python benchmarks/ollama_probe.py
```

前提是现有照片及 `.photo-organizer` 中预处理记录仍在。原始计时与相似度矩阵位于 `benchmarks/results/ollama-probe.json`。

## 后续接入原则

Skill 通过整理引擎调用此服务，不把向量交给智能体逐张计算。模型、量化、接口处理与维度组成索引版本。已有云端 GLM 视觉标签仍属于独立索引，不被这次验证覆盖。全库 embedding、检索质量与并发调度测试等待用户后续授权。

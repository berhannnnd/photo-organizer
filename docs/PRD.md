## 1. 产品定位

用户将大量照片放进本地目录，用自然语言描述自己的整理方式，由智能体理解需求、利用照片索引查找和分类，并通过可靠的文件工具完成整理。

核心目标同时包含三项：

1. **整理自由度**：用户决定条件、类别、层级、归属方式与输出方式，不局限于预设相册或固定标签。
2. **结果准确度**：每项分类有事实依据；缺失信息和模糊判断明确保留，不能为了完成数量而猜测。
3. **重复使用效率**：允许首次索引较慢，将可复用的识别结果沉淀下来；后续查找和整理不反复分析整库图片。

本轮以本地文件为数据源，暂不接云盘接口，不做图片展示、图库、预览服务或对话组件。输出清单和文件执行结果即可验证流程。

## 2. 用户场景与能力边界

| 场景 | 用户示例 | 判断依据 | 整理结果 |
| --- | --- | --- | --- |
| 时间归档 | 按拍摄年份、月份分文件夹 | 可信拍摄日期 | 年/月目录；无日期单独归档 |
| 主体分类 | 猫、狗、食物和其他分开 | 图像主体与已有标签 | 自定义类别；剩余项不丢失 |
| 组合筛选 | 找户外拍的猫，排除有人的照片 | AND/OR/NOT、多主体关系 | 命中、不确定、未分析状态 |
| 场景与活动 | 把聚餐、旅行、工作会议分开 | 场景、动作、物体关系 | 场景分类及依据 |
| 视觉细节 | 找红色雨伞、蛋糕上的生日数字 | 物体属性、局部细节、OCR | 必要时取高清图或裁剪补分析 |
| 主观选择 | 挑适合做旅行封面的照片 | 事先明确的偏好与可观察标准 | 候选、排序理由、待确认项 |
| 自定义层级 | 先按年份，再按旅行/聚会分组 | 元数据 + 语义规则 | 多级目录或逻辑集合 |
| 多重归属 | 同时属于旅行和家庭的照片都保留 | 多标签成员关系 | 一图多相册；物理复制明确计数 |
| 去重整理 | 找完全一样和看起来很像的照片 | 内容哈希、感知相似度及复核 | 精确重复组与近似候选分开 |
| 压缩交付 | 将选中的照片导出为长边 1600px | 可配置变换规则 | 独立输出副本，保留原图 |

自由整理不等于能从图片推断一切。“我去年和小王去杭州的照片”涉及人物身份、拍摄时间和地点；如果缺少 EXIF、用户标注或其他可靠证据，应说明缺失并请求必要信息，不能凭画面编造。

主观和模糊请求需要先判断是否缺少会改变结果的关键信息。不能以“采用默认标准”为由跳过必要追问；也不重复询问用户已明确的条件。用户明确表示“你来决定”或“先随便找一些”时，才采用公开说明的探索标准，结果属于候选建议，不等于已确认偏好。

## 3. 输入、输出与责任分工

### 输入

- 一个或多个用户指定的照片目录。
- 用户自然语言需求，可补充目标目录、分类层级、排除条件、复制或逻辑相册偏好。
- 可选的用户标注、可信侧车元数据；注明来源，不与模型推断混为一谈。

### 输出

- 查找：已判定命中数量、相关候选数量、可分页文件清单、依据、处理覆盖与不确定项；只有指定范围全部评估完毕才报告该范围的完整判定统计，不能把语义判定当成绝对真值。
- 整理：可检查的规则与操作计划、覆盖统计、已执行结果和逐项回执。
- 失败：明确失败对象、原因、可恢复阶段，而不是仅返回“整理失败”。

### 分工

- **Agent/Skill**：理解自然语言，选择处理路线，将需求转成结构化规则，处理歧义，解释结果。
- **视觉模型**：观察画面、生成事实与描述、判断新增语义条件；不负责文件操作。
- **确定性工具**：枚举、解码、索引、压缩、查询、路径计算、复制、校验和恢复。

模型输出必须校验后入库；图片内文字、文件名、网页说明都作为数据，不能成为执行指令。Skill 不应每次临时生成遍历和移动脚本。

### 3.1 跨智能体接入合同

交付形态为独立整理引擎 + CLI + MCP + 轻量 Skill；CLI/MCP 调用同一能力与状态库，不各自维护业务逻辑。“任何智能体”指具有工具调用权限、可访问已授权本地目录或受控服务引用的宿主，不承诺纯聊天窗口能直接操作文件。

- 安装产物必须包含版本化引擎、Skill、CLI 使用说明和 MCP 注册说明；提供能力诊断入口，报告运行环境、模型连接、支持格式、读写范围与缺失依赖。不能默认依赖 Nexus、CC Switch、某个模型账户或某个目录位置。
- 最低工具能力：打开/查看库；同步库；启动/查询/暂停/恢复/取消索引任务；搜索；细化/合并/读取结果集；生成/检查计划；执行/查询执行回执。具体命名和 schema 由技术设计统一，不能要求 Agent 拼接内部文件或 SQL 来补功能。
- 工具响应包含版本、任务/结果引用、状态、数量、覆盖/新鲜度、分页、结构化错误和可用后续动作。列表响应有界，下一页沿用同一结果快照，不把整库元数据塞进对话。原始向量留在引擎，不作为常规工具返回值。
- 至少区分无能力、需澄清、无权限、源离线、版本冲突、预算耗尽、可重试失败；CLI 退出状态和 MCP 结构化响应语义一致，空结果不冒充调用失败。
- 重启会话或切换宿主后，凭持久任务/结果/计划 ID 可以继续；会话文字不是唯一状态源。没有明确结果引用且存在多个可能的“刚才这些”时须澄清，不能猜。
- 本机 CLI 和本机 MCP 为首轮交付范围。远程连接不得直接解释客户端绝对路径；远程认证、上传与引用协议不包含在本轮本地交付承诺内。
- 声称支持的操作系统/宿主版本必须列在发布兼容矩阵，未测平台标为未验证；验收至少包括两种独立宿主，分别通过 CLI 与 MCP 跑通同一任务链、重启续接和缺能力回退，不要求同一平台绑定某个品牌智能体。

## 4. 用户完整流程

### 0. 需求理解与澄清（查找、索引与整理共用入口）

先结合当前会话、用户已经给出的条件与库的可用元数据，区分已知事实、待确认信息和系统建议。需要澄清的判断包括：

| 情况 | 应采取的行为 | 示例追问 |
| --- | --- | --- |
| 目标含糊，决定了完全不同的工作 | 必须追问，不自行选择整理方向 | “你主要想方便找照片、按主题归档，还是清理重复照片？” |
| 日期、人物、地点等指代不明 | 可从上下文可靠确定则复用，否则追问 | “你说的最近，是最近一个月还是这次旅行？” |
| 主观词决定筛选标准 | 先用易选的例子了解偏好 | “你说的有趣，更偏搞笑抓拍、奇特画面，还是有故事感？” |
| 目标目录/归属规则冲突会改变文件结果 | 执行前澄清必要部分 | “同时属于旅行和家庭的照片，要两边都收，还是只放一个位置？” |
| 信息已明确且足以执行 | 直接执行相应已授权步骤 | 不重复询问已有的日期范围和分类规则 |
| 用户也不清楚、希望先探索 | 提供少量多样候选和理由，再用反馈收敛 | “可以先各找一些搞笑、奇特、有故事感的候选，再按你喜欢的方向继续。” |

每轮优先问 1–2 个最影响结果的问题，提供可理解的选项，也允许自由回答；不要一次发长问卷，不要求用户理解模型、索引或阈值。数量等低影响偏好可采用说明过的默认值。必要问题未答复时停在待澄清状态，不能把等待超时当成同意。

澄清期间可以读取已有库统计和索引，不能自行启动未明确范围的大规模模型分析或文件整理。需求澄清与操作授权是不同状态：回答“喜欢搞笑”不等于授权移动或删除图片。

交互状态：理解需求 → 必要澄清 → 形成任务条件；条件仍主观时进入探索候选 → 用户反馈 → 修订条件；条件充分后进入查找/计划/执行。任务记录保存条件来源、待解决问题和当前规则版本，后续轮次继承已确认信息。

### A. 首次建立照片库

1. 扫描文件，记录总数、支持格式、损坏或不支持项目。
2. 建立稳定文件实例与内容身份，发现完全相同的内容但不删除原文件。
3. 提取真实尺寸、方向、EXIF 日期与可用元数据。
4. 生成视觉分析用派生图，原图保持不变。
5. 分批建立基础视觉索引，逐张持久保存；中途退出可从未完成项继续。
6. 返回索引覆盖：元数据完成数、视觉完成数、失败数、未知项及耗时。

不用等全库视觉索引完成才能按日期查找；但部分索引期间的语义结果必须标明覆盖范围。

### B. 用户提出查找需求

1. Agent 通过需求澄清入口形成条件、范围和准确度要求；探索性查找不强迫用户预先定义所有标准。
2. 检查所需信息是否已有索引及覆盖程度。
3. 有足够索引：直接本地查询，必要时对少量边界候选复核。
4. 缺少所需属性：补做相关语义索引，明确这次进入慢路径。
5. 返回结果及覆盖边界，不把“没有标签”解释为“图里不存在”。

### C. 用户提出整理需求

1. 先澄清会改变整理结果的歧义，再确定查找条件、分组规则、目录层级、剩余项处理及输出方式。
2. 对整库或用户指定集合生成完整归属，不能只处理前 N 张。
3. 对歧义、规则冲突和不确定项采用明确策略；需要用户决定时给出具体选项。
4. 固化计划与源文件版本，在已有授权内执行；不对已授权的非破坏操作重复询问。
5. 核对实际输出和计划，返回逐项状态。

### D. 用户调整要求

用户可改分类名、优先顺序、层级、单张归属和主观标准。可直接由索引重新计算的变化不重新看图；只有新增视觉信息需求才补索引。用户修正作为明确的规则/标注保留，不被下一次模型重算覆盖。

### E. 通用任务组合与持续结果集

不按具体问法开发分支。“有趣、好看、有纪念意义、适合分享、类似这张”等只是模糊意图、主观排序、示例检索的测试样本，不各自定义独立功能或永久标签。

统一操作链为：选择输入集合 → 理解/澄清目标 → 检索 → 过滤或排序/挑选 → 分组 → 整理计划 → 执行。操作可按需省略、重排和重复组合；用户“直接整理”可以一次走完检索、分组和执行，无需强制拆成多轮。

系统必须保存可持续引用的结果集：result_set_id、输入范围、条件与版本、成员 asset/file_instance ID、排序与依据、覆盖/不确定状态、库版本、父结果集。展示分页只是视图，不缩小集合。区分当前页面、当前返回的候选集和完整匹配集；不能隐式把第一页或 Top-K 当全部匹配结果。

- “从刚才那些照片里再找没有人的”：在父集合内过滤；不得自行扩大到全库。
- “类似第二张，但不要刚才这些”：这是扩展检索，输入可以是全库减去父集合；范围不清时再追问。
- “把这些按月份分好”：引用明确的结果集并生成计划，不重新搜索，不让新入库文件悄悄进入操作集合。
- “撤掉刚才这个筛选”：回到父集合或重新计算指定条件；不是撤销已执行文件操作。
- “这批先别整理，再加上上次选的”：集合并集后去重，再生成新计划；不变更原计划。

默认整理绑定固定成员快照；用户要求持续更新时才采用动态规则集合。原图变化、丢失、索引更新要显式标记，执行前检查源版本，不能静默替换成员。

### F. 通用模糊意图与偏好学习

1. 区分缺少客观信息、多个合理解释、主观偏好未定义三类问题；只问会改变工作范围、结果或文件行为的关键问题。
2. 用户愿意明确标准时，形成可解释的当前任务规则；用户不知道或委托探索时，以少量多样候选帮助其表达偏好。
3. 反馈统一为：正例、反例、保留/排除、维度偏好、条件修改和范围变更。Agent 把反馈转换为规则与排序更新，不为每个口语短句写独立分支。
4. 每轮继承已确认条件；区分在当前集合内收窄、回退和扩展全库。候选的多样性不能取代实际相关性。
5. 主观判断保存理由与规则版本。默认偏好只用于当前任务，用户明确要求记住时才保存为可修改的长期规则；不得把“有趣”当作人人相同的客观标签。
6. 探索性返回只承诺候选范围；用户要求穷尽查找或完整整理时才按指定范围完成覆盖核算，必要时升级视觉分析。

本轮不开发展示组件，但工具结果要能被 Agent 引用和承接：稳定候选标识、位置、理由、分组、父集合及覆盖状态必须可用。

### G. 三类核心业务场景

| 业务场景 | 通用能力组合 | 完成标准 |
| --- | --- | --- |
| 直接语义搜索并整理；按类型、时间、人物自动或指定分类 | 意图解析 + 澄清 + 混合召回/全量归类 + 自动分组建议或显式规则 + 计划/执行 | 规则明确，指定范围完整覆盖，未知项不猜测 |
| 基于搜索结果自由整理 | 持久结果集 + 自定义层级/归属/命名/输出 + 计划/执行 | 严格作用于选定集合，不重搜、不混入其他照片 |
| 搜索结果二次筛选 | 父结果集 + 增删条件/排序/示例反馈 + 子结果集 | 范围继承可验证，支持继续筛选和回退，未重新分析不必要的图片 |

自动按类型分组需要生成可理解的簇与候选名称，不强制每张图归入某个簇。自动按时间优先事实规则。自动按人物需独立的人脸检测与同人聚类能力，可形成“人物 A/B”并允许用户命名、合并、拆分；通用图像 embedding 或主体标签不能代替同人识别。真实姓名只能来自用户明确标注或可信既有身份映射；非正脸、遮挡与不确定归属保留待确认。一张合照允许属于多个人物集合。

## 5. 索引策略：为了后续自由整理而建立

### 5.1 基础索引

| 层次 | 保存内容 | 用途 |
| --- | --- | --- |
| 文件事实 | 路径、格式、大小、内容哈希、实际尺寸、方向 | 精确过滤、变更检测、去重和文件执行 |
| 拍摄元数据 | 日期及来源、时区是否已知、可用 GPS | 时间与地点条件；未知状态显式保留 |
| 图文向量 | 图片向量、查询/描述向量、模型与预处理版本 | 自然语言召回、以图找图、候选聚类与相似排序 |
| 视觉事实 | 主体、属性、动作、场景、物体关系、可读文字、概括描述 | 支撑多种语义条件，不只固定类别 |
| 质量与相似信息 | 模糊、曝光等可观察质量信息，精确/近似重复关系 | 筛选和整理候选；主观评分可配置 |
| 来源与版本 | 模型、提示/schema 版本、输入派生规格、处理状态 | 解释、缓存复用、失效和重算 |

字段允许未知和不可辨认；不要用伪精确置信度掩饰模型不确定性。标签保留规范词与可扩展事实，避免仅存一个粗分类。

### 5.2 需求专用索引

基础索引不可能提前描述所有细节。用户提出“有红色雨伞且没有人物”“适合旅行封面”等新条件时，可建立以条件版本为键的专用索引：

- 每张图记录满足、不满足、不确定、尚未分析，以及可核查依据。
- 同一条件再次使用直接查询；原图变化或条件定义变化时仅失效相关结果。
- 条件修改不能错误复用旧判断；用户纠正具有明确优先级。
- 对“全部找出来”的需求，补分析覆盖完整指定范围；不能仅审核旧标签召回的候选然后声称没有遗漏。

### 5.3 混合索引与召回架构

采用三种互补索引：结构化事实（日期、尺寸、人物组等）+ 视觉事实/描述/OCR + 图文 embedding。向量进入目标核心架构，具体模型通过对照评测选择，不再把自由语义完全压在固定标签上。

典型查询：解析硬条件与语义目标 → 对可靠元数据施加硬过滤 → 图文向量、标签、描述/OCR 多路召回 → 去重融合与排序 → 必要的视觉复核 → 固化结果集。可先依据索引状态返回明确标注的候选；低覆盖的标签不应用作过早硬过滤，否则会把本可召回的图片排掉。

向量相似度只是候选相关性，不是条件成立的概率。AND/NOT、计数、细粒度关系及主观偏好需要结合结构化事实或视觉复核；“没有人的照片”不能用负向向量相似度直接证明。全量归类必须覆盖所有输入，不能依赖固定 Top-K 保证召回完整。

需求专用索引用于多路召回仍无法可靠覆盖的条件以及用户要求高召回/穷尽时的补分析，不应成为每个新句子都对全库调用 VLM 的默认路径。

对于 1000–10000 张，先评估本地向量矩阵的精确相似度检索；SQLite 管理事实、成员与回执。无需先部署独立向量服务。向量索引可重建；必须绑定模型版本、维度、归一化方法和图片处理配置，不混用不同向量空间。模型加载冷启动与热查询延迟分开测量。

模型选择与验证证据分开管理：图文 embedding 采用可替换 provider，SigLIP 2 与 EmbeddingGemma 2 是候选，不作为所有用户的强制依赖。模型必须用真实中文请求、同义改写、细粒度关系、难负例和本机资源测试验证，官方基准不能代替本项目结论。

截至本次文档修订的已知记录：曾用 Ollama 0.40.8 的 `hf.co/ggml-org/embeddinggemma-2-GGUF:Q8_0` 做五张照片的中英文 smoke test；该模型已按用户要求删除。用户后来下载的 `embeddinggemma-2:latest` 是不同制品，本 PRD 不宣称它已通过同一测试。旧报告只证明旧模型的接入结果，不证明全库准确度，不继承到新制品。当前模型是否可用由能力发现确认；验证必须绑定 provider、endpoint、模型实际 digest/revision、量化、预处理、向量维度和运行版本，而非仅绑定会变化的 latest 名称。详见 [历史本机验证记录](local-ollama.md) 与 [平台调研](embedding-platform-research.md)。本次不重新验证模型。

### 5.4 搜索与全量整理的不同

查找可以先返回候选；是否穷尽应明确说明。全量整理必须满足：

**指定范围内输入实例数 = 已归类实例数 + 未分类/不确定实例数 + 尚未处理实例数 + 失败实例数 + 明确排除实例数。**

以上为互斥的主状态，类别成员另计。一项归入多个组仍只算一个已归类实例。尚未处理或失败不为零时不得报告全范围评估完成；失败项全部记录仅代表本轮任务已结束。处理覆盖率为已完成条件评估实例数/应评估实例数；应评估实例数为输入数扣除有明确规则依据的排除项，不得将失败或未知项改标排除来缩小分母。失败、尚未分析不进入分子，不确定作为已评估但未判定的独立数量报告；分母为零时覆盖率记为不适用。全范围已评估不代表语义召回率 100%，模型可能误判；覆盖与准确度分别验收。

一图多相册时，实例覆盖数与相册成员数分别统计，避免重复成员导致虚假的完整率。

### 5.5 Skill 首次接入：模型配置引导与能力发现

Skill 必须引导用户完成能力配置，而不是假设每个智能体都自带可供脚本调用的模型 API。对话中的智能体能看图，不代表后台引擎能调用它，也不意味着可以取得其账号 token。

按“需求 → 可用能力 → 缺少能力 → 配置或回退”执行，避免一开始要求用户配置所有模型：

1. 识别本次任务：仅按日期/尺寸整理无需询问视觉 API；语义索引、开放语义检索、OCR、同人分组分别检查相关能力。
2. 复用用户已授权的宿主工具、项目配置、环境变量或明确指定的配置来源。CC Switch 是可选导入适配，不是依赖；不扫描无关凭据、不改变宿主的默认模型配置。
3. 展示简短能力清单：已可用、需要配置、可回退和当前不可用；说明这对本次任务的影响。
4. 对缺少的必要能力，优先让用户选择“使用已有 API / 配置本地模型 / 先用受限能力”。提供具体例子，不能只说“请配置模型”。如用户已有明确选择与授权，直接复用，不重复询问。
5. 从用户指定的安全来源读取配置，做少量端到端能力验证；验证通过才进行批量任务。探测须遵守已授权的图片传输范围，不为测试擅自上传私人照片。
6. 保存能力与配置引用、验证结果及版本；不保存明文凭据到索引、任务报告或仓库。后续仅对缺失、失效或本任务新增需求进行追问。

### 5.6 引导用户提供什么模型与配置

| 能力 | 用户可提供的配置 | 验证什么 | 是否必需 |
| --- | --- | --- | --- |
| 视觉理解 | 支持图片输入的多模态模型 API，或宿主明确可调用的看图工具 | 图片确实进入请求、返回有效事实/schema；不是仅文本调用成功 | 详细视觉索引/复杂视觉复核需要 |
| 图文 embedding | 同一图文空间的图片编码和文本编码服务，或本地模型 | 真实图片/文本编码，维度与模型版本一致，向量有限且非零；小样本相关性检查 | 完整开放语义向量检索需要 |
| OCR | 本地 OCR 引擎或 OCR API；也可复用已配置视觉模型 | 能提取文字；若任务需要坐标/版面/数字精度，额外验证 | 按任务启用，不默认强制单独配 API |
| 人物聚类 | 支持人脸检测和同人特征的本地引擎或服务 | 同人/不同人、遮挡、合照专项验证 | 同人归档需要；普通“有人”标签不能替代 |
| 需求理解 | 宿主智能体本身；仅独立无 Agent 运行时另配文本模型 | 能生成合法规则，并承接多轮集合与澄清 | 一般不再向用户索要额外聊天 API |

远程模型需提供：服务商/协议类型、base URL 或明确 endpoint、model ID、认证方式及密钥引用。可选配置包括并发、超时、费用预算、图片传输限制。鼓励给环境变量名、配置文件路径或密钥管理引用，不要求用户将密钥贴进聊天。

本地模型需明确：模型 ID/版本或本地路径、可用执行设备、是否允许下载及下载位置。下载较大权重或安装依赖前说明磁盘、运行环境与预计资源需求，按用户授权执行，不静默联网安装。首次下载与已安装后的离线运行分开说明。

普通文本 embedding 不能直接替代图文 embedding：它可以搜索已生成的照片描述，但不能独立编码原图完成原生文搜图。视觉 API 可看图也不等于提供可复用 embedding。同名模型在不同 endpoint 的能力也不能互相推定。

### 5.7 缺配置时的回退矩阵

| 当前能力 | 能提供的功能 | 限制与引导 |
| --- | --- | --- |
| 视觉理解 + 图文 embedding 都可用 | 混合索引、开放语义召回、必要视觉复核 | 完整推荐路线；仍报告准确度/覆盖，不承诺任意要求都正确 |
| 有视觉理解，无图文 embedding | 建描述/标签索引，做结构化过滤、文本检索与视觉补分析 | 明确开放语义和相似召回受限；可选配置本地图文模型，不能把词匹配冒充等效向量检索 |
| 有图文 embedding，无视觉理解 | 文搜图、以图搜图、相似候选及元数据整理 | 无法可靠提供复杂细节解释、精确否定/计数复核；不把相关候选称为已验证符合项 |
| 无独立 API，但宿主有明确可调用的视觉工具 | 宿主按有界批次看图，再通过 schema 校验导入观察结果 | 保留逐项来源/版本和断点；速度受宿主限制，不从聊天登录态提取 API token |
| 无远程 API，允许本地模型且环境支持 | 本地 embedding/OCR/视觉能力按实际安装情况启用 | 先验证资源与兼容性；装不了就报告，不承诺自动离线全能力 |
| 完全没有可用模型 | 日期/尺寸/格式/路径/精确哈希重复查询、规则整理、复制、压缩 | 明确不具备内容语义搜索和同人识别；缺 EXIF 的图进入日期未知，不编造标签 |
| 没有专用 OCR | 复用视觉工具提取文字，或不建立 OCR 索引 | 金额、日期、小字或位置要求不满足时标记未验证，并引导配置专用 OCR |
| 没有人脸能力 | 仍可做一般语义整理；已有“person”标签可找包含人物的候选 | 不能自动按同一个人归档，不能承诺人物姓名识别 |

宿主视觉回退只有在工具确实存在且允许访问图片时可用，不因为当前聊天模型“理论上多模态”就声称可用。缺少必要能力时，只执行不依赖它且已授权的部分；如果用户要求的结果无法完成，明确解释缺口并保留待配置状态。

回退前说明功能、准确度/覆盖、费用或数据去向的实质变化；用户已选定的配置/回退偏好可复用。同一数据授权与预算内的技术重试不重复打断用户，但不能静默更换外部服务商或上传更多照片。

### 5.8 检索时的依赖与故障回退

- 元数据查询、已有结果集的确定性筛选、基于现有成员的归档计划不需要模型 API。
- 文本向量查询仍需匹配索引版本的文本编码器；若是远程服务，检索时需要一次对应 API 调用。图片已经编码不等于完全不再需要模型。
- 以图查询：库内已有向量可复用；新参考图需要可用的匹配图片编码器。
- 详细复核需要视觉能力；缺少时可返回明确标注的候选，不虚构复核通过。
- 已有索引即使 API 不可用仍可用于可支持的查询；已缓存的查询向量只在模型版本、预处理及规范化查询一致时复用。
- 若编码器不可用，可退到描述/标签/元数据查询，必须说明召回能力变化；不同模型的向量不能混用。更换 embedding 模型需要新建索引版本，不静默替换旧空间。
- 401/403 表示认证或权限问题，429 表示限流/额度，超时表示本次结果未知；分别处理。已完成记录保留，只恢复未完成项；不能用回退结果把未完成索引标成完整。

### 5.9 配置与回退验收

覆盖全新无配置、有部分配置、仅宿主视觉、仅本地模型、已有失效 API、模型切换、离线读取已有索引七类场景。验证：

1. 按日期整理不向用户索要无关模型 API。
2. 语义任务缺能力时能明确说明需哪一种 API/本地能力及如何提供配置；能接受用户选择受限模式。
3. 远程凭据不出现在日志/报告/索引；不尝试提取宿主登录凭据。
4. 文本-only embedding、文本-only聊天模型不会被误认为图文能力。
5. 回退后结果清楚标记实际能力、覆盖和未完成部分，非预期情况下不跨服务商传图。
6. 已有配置只验证/复用，不反复要求用户输入；配置变更后只失效相关派生索引。
7. 检索无需视觉重索引与“检索完全不调用模型”严格区分。

### 5.10 增量同步与索引生命周期

提供快速同步、可选后台监听、完整校验三个入口。快速同步在显式导入/刷新、重新打开库时可触发；后台监听仅在用户启用且宿主支持常驻时运行，不把每个会话变成独立监听进程。监听只是及时发现线索，可靠删除与恢复以成功扫描对账为准。

**身份与变化规则**

文件实例拥有稳定位置身份与历史，内容对象以字节哈希标识；同内容副本共享派生索引，但不同文件实例分别计数。根目录有独立身份，嵌套/重复导入不得重复登记同一个规范化位置；不同库的目录授权和查询作用域不互相继承。

| 变化 | 必需行为 | 分析失效范围 |
| --- | --- | --- |
| 新增文件 | 等待写入稳定，登记实例，按内容哈希查重 | 新内容补齐必要阶段；已有内容复用 |
| 删除文件 | 成功对账后标记实例 missing，新查询排除；保留历史引用 | 不重新分析其他文件 |
| 改名/移动 | 在有可靠文件身份或唯一证据时续接实例并更新位置 | 内容未变则复用；匹配有歧义时登记新/缺失实例而不是猜 |
| 同路径替换图片 | 创建新内容关联，旧结果保留旧版本 | 新内容对应阶段重做 |
| 仅时间戳变化 | 重新核验内容，不仅凭 mtime 猜 | 字节哈希未变则仅更新文件状态 |
| EXIF/元数据变化 | 刷新元数据与日期条件结果 | 只有证明规范方向、色彩及实际视觉输入未变，才复用视觉结果；否则重做相关阶段 |
| 模型/提示/预处理变化 | 创建新的阶段版本 | embedding 变化只重建向量；视觉模型/识别提示变化失效对应视觉阶段及依赖判断；仅分组规则变化复用有效识别事实，新增语义另补分析 |

快速扫描可先用大小、mtime 等筛出疑似变更，但不声称能发现所有同大小同时间戳篡改；完整校验重新计算内容哈希。文件复制/连续写入产生的事件需合并，检查读取前后状态；未稳定的文件保持待处理，设有限重试，不循环无限等待。

**扫描与删除语义**

- 每次对账记录 root、scan_id、完成范围及时间。仅在相应目录成功枚举完成且期间事件已协调时确认缺失；子目录权限错误不得扩大为整库删除。
- 根目录不可访问、移动盘卸载或网络断开标为 offline；暂停对应扫描/执行，保留索引。可以显式查历史索引，但返回结果必须标离线，不能承诺原图可读取或可整理。
- 没有监听能力时回退快速同步，明确 last_successful_scan 和新鲜度未知；不能声称实时更新。
- 删除实例后，仍被其他在线副本引用的内容索引不清理。无引用内容默认保留 30 天（可配置）；历史结果/计划仍引用的记录保留身份和回执，缓存按策略延迟回收。清理只影响本工具派生数据，不删除原图。
- 用户移除库配置与删除照片是不同动作；默认停止监听/同步，是否清理该库索引单独说明。恢复同内容文件时可复用有效缓存。

**版本一致性与查询**

阶段任务绑定输入内容与处理版本。回写时检查是否仍是目标文件的当前版本；过期任务结果可保存为旧内容缓存，但不能覆盖新文件关联。新旧向量空间分开存放，重建完成前不得将两个空间混合查询。

新文件元数据可先用，视觉未完成时明确计入未分析。查询返回库版本、同步时间、相关阶段覆盖和离线/变化情况；用户要求最新完整整理时先完成范围对账与必要补索引。若来源不可访问或预算不足，返回未完成并解释，不用旧数据伪装完成。

已有结果快照不自动扩张或替换成员；成员改名在身份可靠时可更新定位信息，内容变化则标 stale。新操作计划检查源内容版本。默认排除索引缓存和本工具导出目录，避免复制结果被监听再次导入形成循环；用户显式导入导出目录时仍按副本规则处理。

增量验收必须覆盖：新增/删除/改名/副本/同路径替换、写入中途、根离线、部分扫描失败、监听漏事件、读取期间变更、迟到分析结果、缓存恢复、输出目录回流。一次失败扫描不得将整库标为删除；无变化同步不得新增视觉调用。

### 5.11 查询判定、范围与不确定性合同

为每项条件保留四种状态：满足、不满足、未知（已检查但证据不足/冲突）、未分析；执行错误另作任务状态记录，不能当作不满足。向量召回的相关候选不自动获得“满足”判定，模型判定附来源与版本，仍可能误判。

布尔组合采用保守三值逻辑，未分析在计算时作为未知但保留原因：NOT 未知仍未知；AND 任一不满足则不满足、全部满足才满足；OR 任一满足则满足、全部不满足才不满足；其余未知。标签中没出现 person 不是“没有人”的证据。已确认的其他条件可以短路，无需为不影响结果的条件额外调用模型。

- 探索模式允许返回相关候选并排序，标明它不是完整条件匹配集；候选为空不等于图库里不存在。
- 条件筛选默认只将满足项放入命中集合，未知/未分析另列数量与可继续操作的集合；不得为了凑数直接归类。
- 用户要求全范围查找时，全部应评估项须得到评估或明确失败状态；失败、未知、尚未分析与覆盖分别报告。“全范围已评估”不等于“所有语义判断都正确”。
- 后续筛选继承明确父集合和版本；若新条件改变所需证据，只对该作用域补分析。放宽已丢弃的条件可能需要返回上级范围重新计算，不能在已裁掉的子集内声称恢复全部结果。
- 同一字段冲突默认用户明确纠正优先，其次可信原始元数据，最后模型推断；保留被覆盖证据。日期与视觉推断不是等价事实源，不以视觉猜测覆盖 EXIF。
- 主观规则没有全局真值，保存偏好定义、样例和规则版本；跨任务复用遵守用户授权。结果集合的并/交/差默认按文件实例，按内容去重须显式指定并保留副本映射。

## 6. 自由规则与执行计划

“整理自由度高”的验收定义不是支持多少句话，而是不改代码能否组合这些维度：

- 范围：全库、目录、上一结果、手选集合，以及交并差。
- 条件：语义、日期、主体/人物、视觉属性、示例、AND/OR/NOT。
- 结构：用户指定类别或自动分组；多级目录；一图多类或唯一归属。
- 决策：排序、择优、去重候选、排除、人工纠正与未知项处理。
- 输出：虚拟相册、复制目录、文件命名模板、压缩导出；不暗含删除权限。
- 多轮：继续收窄、扩展、回退、重新分组和修改偏好，保留作用范围及历史。

以上维度可组合才算通用；仅固定“旅行/宠物/食物”类别或为“有趣”写专门判断不满足目标。规则模型相应表达输入集合、日期口径、条件、层级、命名、排序、冲突、未知项和输出。

例：用户说“按年份整理，里面再分旅行和聚会，其他单放，不要改原图”。

对应规则为：使用可信拍摄年份；第二层采用旅行/聚会语义条件；同时命中的图片按用户选择的一图多组或明确优先级处理；未匹配进入其他；日期缺失进入日期未知；复制导出到指定目录。

不得悄悄将任意自然语言降级为关键词 OR 匹配，也不能把主观选择伪装成客观事实。日期、人物身份和地理位置等证据缺失时，优先指出缺口。

计划应保存源实例和内容哈希、规则版本、目的相对路径、操作类型、依据与状态。重新运行同一计划应幂等；重新创建计划与重放旧计划是不同操作。

### 6.1 规则边界与确定性执行

本轮必须支持多级组合（至少覆盖三层混合分类的验收），不能只做一个 group_by。每层可以是事实字段、自定义条件或已固化的自动分组；有层数/路径长度上限时由能力接口明确告知，超限拒绝并解释，不能截断规则。

- 自动分组先形成可命名的类别与成员建议，用户可改名、合并、拆分、调整优先级；计划保存具体规则和成员，执行时不让模型重新分组。同一快照与规则的重算应稳定；模型/参数变更产生新版本。
- 重叠类别的默认物理策略为唯一归属；规则存在重叠且未指定优先级时列出冲突并澄清，不擅自采用首次命中。逻辑相册可一图多类；用户选择复制到多个目录时，报告唯一照片数和实际副本数、预计字节。
- 不匹配进入未分类；证据不足进入待确认；日期缺失进入日期未知；损坏/失效源进入失败。这些类别分开，不能都塞进“其他”掩盖问题。用户可改名称，但统计状态不改变。
- 命名模板至少支持拍摄年月日、类别、原文件名、序号、短资产标识；缺值策略为明确占位或保持原名，不编造日期/姓名。模板不执行任意表达式。非法字符、保留名、大小写/Unicode 冲突和路径过长在计划阶段报告，采取确定性追加标识或请求修改规则，不覆盖目标。
- 用户更改单张归属默认仅作用于当前集合/规则版本；用户明确选择后才推广为通用分类规则。重索引保留有效用户纠正，照片内容改变时提示重新核验。
- 同一计划重试按动作 ID 对账；新计划即使内容相似也不得未经检查覆盖旧输出。重复计划提示可复用的已有结果或新目标目录；相关冲突有明确处置后才执行。
- 默认对失败项记录并继续不相关且安全的动作；同一目标命名空间冲突、源根离线或计划整体失效时暂停相关范围。回执区分成功、失败、未执行、冲突，不以进程退出成功表示所有文件成功。
- 逻辑相册保存持久成员，不复制原图；复制导出核验源与目标哈希；压缩导出核验可读、尺寸/格式/质量要求并记录输出哈希。指定最大字节时必须满足或明确失败，不以单次 quality 参数代替大小保证。
- 不提供自动撤销已执行文件操作的承诺；本轮提供回执、对账和恢复，筛选历史回退不等于文件回滚。原地移动/删除仍不在本轮执行能力内。

## 7. 预处理与原图保护

- 通过实际解码确认格式与尺寸，不单靠扩展名。
- 正确处理方向、色彩和透明度；派生图不放大小图。
- 视觉输入初始可采用长边 1280px、JPEG quality 82；这些是待验证参数，不是普遍最佳值。
- 小文字或关键细节看不清时升级输入分辨率或读取原图局部，不能持续拿低清图猜测。
- 感知相似只生成近似候选；相似不代表应删除。
- 原图、分析派生图和压缩交付文件分开。本轮所有导出均保留原图；用户要求原地覆盖时明确说明超出当前能力范围，不绕过执行合同。
- 缓存按内容和转换参数版本复用。多个相同文件可共用视觉结果，但各自位置仍可追踪。

时间归档默认优先可信 EXIF 拍摄日期。用户明确指定按导入/修改日期时才能采用对应字段；不得自动用下载日期替代拍摄日期。时区未知时不擅自换算。

## 8. 快慢路径与性能目标

| 操作 | 是否允许模型调用 | 预期 |
| --- | --- | --- |
| 初次基础视觉索引 | 允许 | 可慢、可恢复、有覆盖统计 |
| 新增未覆盖语义条件 | 允许 | 首次补分析；结果可复用 |
| 已覆盖条件查找 | 元数据/标签过滤不调用；向量查询按需调用匹配文本编码器 | 不重新分析原图；远程查询编码延迟单独计入 |
| 对已有事实/分类作确定性重分组 | 不调用 | 快速生成新计划；新增语义分组另走分析路径 |
| 边界或高准确度复核 | 按需调用 | 明确额外延迟和复核范围 |
| 复制/压缩执行 | 不调用 | 耗时由数据量、存储与变换决定 |

1000 张测试库的初始性能目标：查询向量已给定时，本地检索内核 p95 ≤200ms；含本地热 embedding 的搜索工具端到端 p95 ≤1s；计划生成和逻辑相册提交各 ≤1s。详细计时边界与负载条件见 9.5。它们是待验收目标，不是当前实测承诺。

还要单独测 Agent 解析需求到返回结果的端到端时间，不能只用 SQL 耗时代表用户等待时间。物理复制和压缩完整报告处理字节、速度与最终完成时间。

不为了达成速度目标而减少整库覆盖、跳过错误或降低应有准确度。若准确度不足，应改进观察质量、条件定义或复核流程，并报告速度代价。

### 8.1 长任务、预算与并发合同

索引、同步、批量复制/压缩以持久任务运行。创建任务快速返回 task_id；状态查询返回阶段、总数/已完成/失败/未处理、已消耗预算、覆盖版本和可执行动作，不要求一个工具调用持续阻塞直到完成。

状态至少区分 queued、running、pausing、paused、cancelling、cancelled、completed、partial_failed、failed、needs_input。未完成任务不能用 completed 掩盖错误；中断后任务可恢复，对已完成项不重放。缺配置/权限/必要澄清或预算耗尽进入对应待处理状态。

- 暂停/取消请求先持久确认并停止派发新工作；已在途的模型请求无法保证供应商停止计算或计费，结果可留缓存但取消任务不再发起新副作用。运行中的文件动作在安全检查点完成或留下可对账临时状态。取消已确认与所有在途工作结束分别呈现。
- 单项 transient 错误默认最多额外重试 2 次，指数退避并尊重 Retry-After；认证/配置错误不自动重试。模型超时的可能计费与尝试次数记录，重试限于无文件副作用的分析；文件写入必须先对账。
- 用户可设图片数、模型请求数、运行时长和费用预算。未知价格时不宣称能严格控制金额，使用请求/图片上限并报告 token usage。预算检查包含在途工作预留；达限停止新派发，明确可能存在的在途消耗，不自动换服务商继续。
- 同库索引与查询并行，查询读取稳定已提交版本；后台推理使用有界小批次与低优先级队列，交互查询优先，防止长批次挤占所有推理资源。不同 provider 分别限流，外部服务无法保证的调度能力须显式说明。
- 同一资产/阶段/版本的重复索引请求合并。多个 Agent 可读同库；同一文件目标或同一计划的写操作串行/互斥，不能由两个会话同时执行。锁有持久所有权与崩溃恢复机制，不能只靠对话约定。
- 新任务或配置变化不篡改正在执行计划的规则。资源不足时降低索引并发或暂停，不能无限排队、耗尽磁盘，或假装查询正常。支持显式停止后台监听且不删除照片或既有索引。

## 9. 准确度与验收方案

### 9.1 评测任务

1. 有/无拍摄日期、日期范围、多级日期目录。
2. 单主体、同义词、中英文表述。
3. 多条件 AND/OR/NOT、主体与属性关系。
4. 活动/场景分类、同图多类、用户类别优先顺序。
5. 新语义条件补索引及重复使用。
6. 主观选择：依据与排序可解释，不假装存在唯一真值。
7. 压缩导出、完全重复与近似候选。
8. 新增、修改、删除文件后的增量更新。
9. 失败恢复与重复执行。
10. “帮我整理一下照片”必须先澄清目标，不能直接全库分类或移动。
11. “有趣的照片”覆盖偏好明确、用户不知道、用户明确委托、拒绝部分候选、跨轮修改五种分支。
12. 必要澄清未答复不得执行依赖步骤；已有答案不重复提问；支持用户从探索转向全库整理。
13. 三大业务场景各设计多组未在开发示例中出现的表达与任务组合；验收按能力评估，不按关键词命中评估。
14. 二次筛选严格属于父集合；扩展搜索需要明确作用域；分页不丢成员；撤销筛选不误撤销文件操作。
15. 人物聚类测试相同人物不同场景、相似人物、遮挡和合照，并验证命名/合并/拆分；没有这个专项测试不能声称已支持按同人整理。
16. 向量、标签、混合检索使用同一标注集合做对照，分别测 recall@K、排序相关性和最终 precision/recall；记录中文效果、冷/热耗时及峰值内存。

### 9.2 质量指标

- 确定性元数据/文件操作：可验证字段和计划输出准确一致，覆盖账本无漏项，原图哈希不变。
- 客观语义：用独立标注的样本测 precision/recall，分条件和类别报告，不只给一个平均数。初始目标：常见主体 precision ≥95%、recall ≥90%；复杂条件单独测，达不到则明确标记未通过，不以降低样本难度通过。
- 不确定项：报告比例、原因和处置；不能全部移入不确定来虚增准确率。
- 主观任务：评审标准、用户接受率与修改次数；没有用户评审时不能宣称已验证偏好准确度。
- 澄清质量：必须追问场景的遗漏率、不必要追问次数、用户完成任务所需轮次；对必要信息缺失却直接执行的测试用例，零容忍。
- 探索质量：首轮方向多样性、重复候选率、用户反馈后的接受率变化；保留反馈后仍无改进的失败样例，不仅测试模型能生成理由。
- 模型索引完成率不等于分类准确率。小样本复核不等于全库准确率。

评测样本要覆盖正例、难负例和边界例，并包含随机样本。独立人工标注尚不可得时，可先做 Agent 视觉复核，但必须标成模型辅助评测，不叫人工真值。

### 9.3 现有 1000 张数据怎么使用

继续使用已有数据，不重新下载或生成照片。这批图片用于真实规模、文件流程和部分语义测试；它来自多个公开来源，含历史照片和扫描件，不能当成真实家庭相册分布。

来源标题和下载搜索主题不能当视觉真值。先做元数据审计。若缺少 EXIF，不编造日期；日期边界另用隔离的程序化小型测试文件验证，不能将其混入真实照片集。

先单图验证实际 provider/model 的视觉能力，再小批、全量；记录请求、输出 schema、时间、token usage 和失败类型。401、429、超时和无效结果分别处理，不声称为“不支持图片”。

### 9.4 必须通过的工程验收

- 原图不变，所有输入可追踪。
- 不覆盖已有目标，不允许路径越界或符号链接逃逸。
- 中断后先对账，已完成动作不重放。
- 用户修改源或输出后发现冲突，不能无条件继续。
- 索引可续跑，查询显示索引覆盖与新鲜度。
- 已覆盖条件重复查询/整理不重新调用视觉模型分析原图；查询 embedding 编码与缓存命中单独计数。
- 修改分类规则不需要重做全部基础视觉索引。
- API mock 单测与真实模型调用证据分开保存。

### 9.5 固定评测协议

以下数值是 v0.6 的拟定验收门槛，不是已实现成绩。测试前固化照片哈希、查询集、模型/运行配置、机器规格、随机种子和数据划分；调参不得查看保留测试结果后反复挑选最好的一次。

**数据与语义评测**

- 现有 1000 张按内容/近重复组分离：200 张用于开发，300 张为保留质量评测集，另 500 张用于规模与扰动测试；全库用于性能和完整性测试。若保留集被用于调参，应更换未用于调参的保留划分并明确记录，不能继续称作盲测。
- 至少 60 条质量查询，覆盖常见主体、场景/属性、组合/否定/计数、同义改写、示例检索、复杂关系六组，每组至少 10 条；另至少 12 条多轮任务链覆盖三大业务场景、模糊澄清与反馈，不为单一具体问法设置特例。
- 每条客观查询在完整 300 张评测范围逐图标注满足/不满足/有争议，不能只标模型召回结果，否则无法测漏召回。人工独立标注并复核争议；仅 Agent 复核时结果标模型辅助，不判为正式人工质量门禁通过。正例不足的类别报告不足，不用零正例查询抬高指标。
- 常见主体门禁每个评测类别至少 20 个有效正例，precision ≥95%、recall ≥90%；其他客观复杂条件初始目标 precision ≥90%、recall ≥85%，逐组报告及总体 macro/micro，不能以总体均值掩盖某组不达标。难以满足的数据条件进入待补证据，不隐去该能力。
- TP/FP/FN 以独立真值为准；未返回的真实正例包括模型判未知和未分析项，均计入 FN。零预测的 precision 标 N/A，不能写 100%；有争议真值单列并报告占比，不无声删去难例。重复副本按内容统计语义质量，文件执行另按实例计数。
- 召回阶段报告 recall@10/50 和精确召回范围，最终结果报告 precision/recall；相关性分级明确后才报告 nDCG。条件正确性与排序分开，不把排序相似度当真值概率。
- 主观任务采用明确偏好下的用户接受率、反馈前后变化与完成轮次，不设假想客观准确率；没有用户评审就标主观验收待完成。人物聚类若现有数据缺少足量已知同人/不同人及合照样本，需用户授权的专项测试集，缺证据不能宣称该功能通过。

**性能评测**

- 主基线为现有 1000 张库，模型版本和硬件固定。使用至少 20 个不同查询，各重复 10 次；分别报告首次加载、热模型但无查询向量缓存、已有查询缓存三种结果。成功率和错误数同时列出，失败请求不从统计中静默移除。
- 本地检索内核（向量已给定，包括过滤、候选融合、结果存储和首批返回）p95 ≤200ms；本地热 embedding 的搜索工具端到端 p95 ≤1s；对 1000 项既有判定生成计划、提交逻辑相册各 ≤1s。新增语义分析、远程网络编码和 Agent 推理单列，不能混进内核指标也不能从用户总耗时中隐去。
- 后台索引运行时使用同组查询再测，工具热查询 p95 ≤2s 且不超过空闲基线的 2 倍；达不到须调小批次/并发或标明未达标。取消/暂停控制请求确认 p95 ≤1s，在途执行结束耗时单列。
- 自然语言端到端任务按每种宿主至少 12 条链、每链 3 次记录；必须同时满足作用域、澄清与文件结果正确性。该指标用于确定宿主实际体验，不以某个 SQL 基准替代。
- 复制/压缩分别报告全量完成耗时、字节、吞吐、成功/冲突/失败，不设不依赖设备的统一秒数。10000 张能力若没有独立规模实测，发布时仅标设计目标，禁止从 1000 张线性推算已支持。

## 10. 交付范围与顺序

完整目标包含上述自由规则、可复用索引、准确度验证和可靠执行。实现顺序不意味着削减最终目标：

1. **基础闭环**：独立引擎与 CLI/MCP、配置诊断、本地扫描和增量对账、元数据、派生图、任务/状态库、日期查询、计划、逻辑相册和复制/压缩执行。
2. **语义闭环**：图文向量与真实视觉事实混合索引、持久结果集、组合条件、需求专用索引、自动/自定义分组、多级整理、人物聚类及用户修正。
3. **质量闭环**：独立评测集、细节升级复核、准确度与端到端性能验证、增量与故障恢复验收。
4. **扩展能力**：近似重复与事件聚类增强、更多格式、云盘适配。

原地移动/删除、未经用户标注的真实身份推断、RAW/Live Photo 全支持需单独明确合同和验收，本轮不以临时脚本补齐。云盘与展示层不阻塞本地核心流程。

## 11. 基线与后续决策

本版已将审查发现的六项缺口转为目标合同与验收入口。它可以作为后续技术设计和实现的输入，用户现已批准启动开发；目标合同不代表已交付任何新增能力。

模型默认值、自动分组算法和硬件批次参数以独立基准决定；不改变此处的作用范围、未知处理和原图保护语义。验收数据不足、宿主不支持或模型能力缺失时显式记录限制，不宣布对应完整能力完成。

按用户最新授权推进实现，逐项维护交付清单。真实模型接入与质量测试沿用已授权配置和数据范围，开发单测不替代社区发布验收。
